# Changelog v34.8.3: Message Timestamp Preservation Fix

## Critical Bug Fix
- Fixed CASCADE DELETE issue causing message timestamps to be overwritten on every save operation
- Changed `INSERT OR REPLACE` to `INSERT ... ON CONFLICT DO UPDATE` in `saveSession()` to prevent session row deletion
- Modified message save logic to skip existing messages during full saves, preserving original `created_at` timestamps
- Added `getMessagesForSession()` method to retrieve existing message indices before save operations

## Usage Statistics System
- Implemented comprehensive usage statistics tracking and visualization
- Added new backend service `backend/data/usage-statistics.js` for token usage aggregation
- Created interactive chart UI with provider/model filtering and date range selection
- Added CSV export functionality for usage data analysis
- Integrated cache invalidation system to ensure fresh statistics after data operations

## Database Optimizations
- Added database index on `messages(created_at, provider)` for faster usage statistics queries
- Enhanced `upsertMessage()` to preserve original timestamps during updates
- Extended `addMessage()` with optional `createdAt` parameter for timestamp control
- Improved message save performance by skipping redundant database operations

## Code Quality
- Added comprehensive debug logging to usage statistics service
- Improved error handling in IPC handlers for usage data
- Enhanced message save transaction logic with insert/skip counters
- Better separation of concerns between incremental and full save operations
