### 1b64da2: feat: Add 'Use Worker Thread' toggle in Accessibility Settings
**Changes:**
- Added toggle in Accessibility Settings to enable/disable markdown worker
- Default: enabled (backwards compatible)
- When disabled: Forces all markdown parsing to main thread (md.js)
- When enabled: Uses worker (md.worker.js) for heavy content (>3KB, code blocks, LaTeX)

**Implementation:**
- Added useWorker to state.settings (default: true)
- Added UI toggle with help text explaining the feature
- Modified worker decision logic in both md() function and performSmartRender()
- Added event listener with toast notification on toggle
- Added backwards compatibility check in load() function

**Purpose:**
- Allow testing pure main thread performance vs worker overhead
- User can benchmark which is faster for their content type
- Useful for debugging/testing markdown parsing performance

### 66641c1: docs: Add comprehensive markdown parsing flow and performance analysis
- Analyzed dual-mode parsing (md.js main thread vs md.worker.js background)
- Documented worker usage triggers (3KB+, 3+ code blocks, LaTeX)
- Detailed smart throttling system with 6 modes (none to minimal)
- Identified root causes of perceived response delays:
  * Throttling intervals (50-150ms default)
  * Worker communication overhead (30-90ms per cycle)
  * Full re-parse on every update (no incremental parsing)
  * Cache not used during streaming
- Provided quick wins and advanced improvement recommendations
- Added performance metrics and test cases
